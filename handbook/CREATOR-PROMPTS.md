# 鳥寶創作室：提示詞與本機流程

這份說明對應 v0.3 的本機「鳥寶創作室」。它是原創提示詞及圖片檢視工具，不是 AI 圖片服務。網站沒有呼叫圖片 API、沒有上傳照片、沒有登入或付費功能。是否使用其他工具、是否把自己的參考照交給該工具，由使用者另外決定。

## 使用流程

1. 選一張自己有權使用、沒有拍到人臉與個人資料的鳥寶參考照。JPG、PNG、靜態 WebP，10 MB 以內且不超過 2400 萬畫素。網頁會縮成最長邊 720 像素的參考圖，重新編碼移除原檔拍攝資訊；只在記憶體，不寫入相簿、遊戲存檔或下載的提示檔。
2. 填鳥寶暱稱、羽色及短短的羽色小記。暱稱只用於本機介面，不會進入提示詞；提示詞不包含照片本身、本機路徑、原檔名稱、拍攝資訊或任何服務憑證。羽色小記只應描述羽毛，不可填個人資料。程式會拒絕常見網址、電子郵件、長電話數字及敏感欄位文字，但這不是完整的個資辨識系統，仍需使用者自行確認。
3. 複製或下載原創提示詞，自己選擇是否使用其他圖片工具。若下載或剪貼簿受瀏覽器限制，提示全文仍在可選取文字框中。
4. 將圖片工具產生的「靜態 16 格角色動作圖」匯入預覽：1280×1280、4×4、每格 320×320；PNG 或靜態 WebP，8 MB 以內。程式檢查實際圖片標頭、解碼尺寸、透明像素及每格非空，再重新編碼成 PNG，移除原圖中繼資料。重新編碼的 data URL（含前綴）上限為 12,000,000 字元，與小屋動態模組一致。GIF、SVG、動態 PNG／WebP、JPG 動作圖、尺寸錯誤、不透明背景、空格或超出處理後上限會拒絕；驗證失敗不取代原先可用的動作圖。
5. 看過 16 格並試走路／飛行。確認每一格都是同一隻完整、自然的鳥，再勾選並按「這次用我的鳥寶」。自動檢查不能辨認鳥的身分、解剖或動作正確性，不能代替這一步。

選擇圖片不代表已生成動畫。網頁只是播放靜態動作圖中的格子，並在預覽範圍移動；它不能自動補畫缺格或修復 AI 生圖錯誤。若圖片工具不能直接輸出正確規格，請先在該工具或其他已獲授權的編輯工具調整，不能把不合格圖描述成成功。

## 16 格動作順序

由左至右、由上至下。程式索引從 0 開始，介面顯示第 1～16 格。

| 程式索引 | 動作 |
| --- | --- |
| 0～3 | 自然站立、眨眼、小幅歪頭、羽毛輕微起伏 |
| 4～7 | 自然側向走路四格循環，交替踩步 |
| 8 | 低頭喝水姿勢，不畫水碗 |
| 9 | 低頭啄食姿勢，不畫食物或食碗 |
| 10 | 回頭整理肩部羽毛 |
| 11 | 放鬆站立、微張嘴唱歌，不能畫成呼吸困難 |
| 12～15 | 真實翅膀關節與初級飛羽的四格拍翅循環 |

角色維持向左的三分之四／側面方向。站立時腳的基線在每格約 y=285；完整冠羽、尾羽、腳趾與飛行翅膀都在各自格內。不要添加衣服、帽子、飾品、玩具或背景。

## 原創提示詞模板

正式頁面的 `CottageCreator.makePrompt()` 會由已選羽色和經驗證的羽色小記組成同一份英文提示。模板只說明角色的外觀與輸出規格，不包含真實個資或來源機密。下列為純模板摘要，不是任何真實鳥寶的照片紀錄：

> Create one original photorealistic cockatiel animation sprite atlas using the reference bird photo that I choose to attach separately. Output exactly 1280 × 1280 pixels, transparent RGBA PNG, 4 columns × 4 rows, 16 equal 320 × 320 cells. Preserve one consistent natural cockatiel character. No text, labels, grid lines, backgrounds, accessories, or extra animals. Use frames 0–3 for idle, 4–7 for walking, 8 for drinking, 9 for eating, 10 for preening, 11 for singing, and 12–15 for flight. Keep every complete bird inside its own cell, with genuine alpha transparency.

## 想做不同版本？可以接著貼

換另一種玄鳳羽色（附上自己有權使用的動作圖）：

```text
請保留這張玄鳳 4×4 動作圖的 16 格位置、角色大小、姿勢、方向與透明背景，只把羽色改成【填寫羽色特徵】。每格必須仍是同一隻玄鳳，尾巴、冠羽、腳趾和翅膀完整在格內。輸出靜態 1280×1280 透明 PNG；不要加文字、相框、衣服或場景。這只是外觀，不要替牠指定個性。
```

用自己的照片做角色：先在創作室選「依照我自己提供的鳥寶參考照片」，填羽色小記，再複製完整提示詞。照片不會自動跟著複製；由你自己決定要不要另附給圖片工具。不要把自己的照片加入公開程式碼包。

改成另一種鳥的網站（貼給程式助手）：

```text
請先讀目前專案。我要另存一份【填鳥種】版本，保留玄鳳原版。先確認物種及可靠獸醫來源，列出哪些教材可以保留、哪些飲食與安全內容必須重查。不要把玄鳳資料直接當成所有鳥都適用；沒有證據的食物標資料不足。角色可參考我有權使用的照片；先固定外觀，再做同一角色的 16 格走路與飛行。保留繁體中文、圖卡、鍵盤、靜音、減少動畫與本機隱私。不要自動安裝、登入、上傳照片或發布。先完成可預覽版本，報告實際測試和專業審閱缺口。
```

## 程式整合

`CottageCreator.render()` 回傳 HTML；頁面放入 DOM 後呼叫 `mount(container)`，切換頁面前呼叫 `unmount()`。`unmount()` 停止預覽、移除監聽與釋放下載 URL，但保留本次頁面工作階段的參考圖／動作圖，方便回到小屋再回來繼續；完整重新整理會清除。沒有 localStorage 或 IndexedDB 寫入。

使用者明確勾選並套用後，從 window 發出：

```js
new CustomEvent('CottageCustomBird', {
  detail: {
    dataUrl: 'data:image/png;base64,…',
    ack: (ok, message) => { /* 由創作室提供的確認回呼 */ }
  }
})
```

外層接收者在動態模組接受圖片後，必須呼叫 `detail.ack(true, '已套用')`；若驗證失敗，呼叫 `detail.ack(false, error.message)`。創作室只在收到 true 後才標示成功，沒有接收者或 2 秒內未回覆會保留原選擇並提示尚未確認。接收者可在 render 前或後回覆，回覆是本機函式，不是網路請求。

選「回到原本的鳥寶」或移除已套用動作圖時，同樣發出帶有 `ack` 的事件，但 `dataUrl` 為 null。小屋動態模組由外層接收，創作室不直接修改 Motion、相簿或遊戲資料。暱稱不放在事件裡。

動作預覽尊重現有頁面的減少動畫設定與系統減少動態偏好。這份創作不需要登入，也沒有公開分享。若將來增加自動生成、帳號、跨裝置保存、公開上傳或付費服務，必須另外取得所需授權與設計安全流程。
